# Crypto Promo Hunter

MVP Telegram-бота на Python 3.12, aiogram 3, PostgreSQL 16, SQLAlchemy и Alembic. Проект добавлен отдельно от существующего статического фронтенда; HTML-файлы фронтенда не изменены.

Пользователь подписывается на Bybit, Bitget и MEXC, просматривает активные акции по одной карточке с пагинацией, сохраняет их, выбирает напоминание за 1 или 24 часа, RU/UA и часовой пояс (Europe/Kyiv по умолчанию). Рассылку можно отключить. Бот не торгует, не запрашивает ключи бирж и не подключается к аккаунтам.

**Bybit: автоматический сбор официальных анонсов с модерацией подтверждён 2026-10-08. Bitget и MEXC: пока ручной импорт.** Bybit получает данные из публичного HTML/JSON официальной страницы без API-ключа и без настройки LINK_SELECTOR. Пользователь получает уведомления после одобрения администратором. В деморежиме все акции вымышлены и Telegram вообще не используется.

## Быстрая проверка без токена

```bash
cd crypto-promo-hunter
cp .env.example .env
# Никаких секретов для демо не требуется.
docker compose --profile demo up --build --abort-on-container-exit --exit-code-from demo
```

Поднимается отдельная PostgreSQL-база `demo-db`, выполняются миграции и демонстрационный сценарий: три вымышленные акции, подписки, сохранения и напоминания. Процесс печатает карточку и завершается. Начальная загрузка не рассылается; задания модерации выводятся только в stdout с меткой DEMO. Даже если передать BOT_TOKEN, DEMO_MODE=true никогда не создаёт Telegram-клиент. Ссылки демокарточек ведут на главные страницы бирж, а не на настоящие акции. Повторный запуск обновляет те же записи, не создавая дубликаты.

Демо и production используют разные volumes. `docker compose --profile demo down` останавливает контейнеры, сохраняя демобазу. Не удаляйте production volumes без резервной копии.

## Создание и запуск настоящего бота

1. Откройте официальный @BotFather в Telegram, выполните `/newbot`, задайте имя и username. В `/setcommands` можно зарегистрировать `start`, `timezone` (пользовательские), `admin` и `stats` (администраторские).
2. Добавьте токен **локально** в игнорируемый `.env`: `BOT_TOKEN=...`. Не отправляйте его в чат и не коммитьте. Укажите свои числовые Telegram ID через запятую в `ADMIN_IDS`. Определить ID можно по собственному Telegram update или через доверенный инструмент; имя пользователя не является ID.
3. Задайте уникальный `POSTGRES_PASSWORD` и такой же пароль в `DATABASE_URL`. URL должен указывать на compose-сервис `db`. URL-кодируйте специальные символы пароля. Изменение пароля в `.env` не меняет пароль уже созданного PostgreSQL-volume.
4. Оставьте `DEMO_MODE=false`, `AUTO_PUBLISH_VERIFIED=false`. Запустите:

```bash
docker compose --profile live up --build -d
docker compose --profile live logs -f bot
```

Бот применяет миграции и работает через long polling; публичный веб-сервер и webhook не нужны. Запускайте только один polling-процесс на токен. Для доступа к Telegram нужен исходящий HTTPS к `api.telegram.org`. Проверьте `/start`, выберите биржи, импортируйте и одобрите карточки. Не проводите тесты рассылки на настоящих подписчиках.

Если облачный прокси ограничивает сеть, добавьте необходимые официальные домены в настройки среды. Значения секретов вводите только в локальном `.env` или защищённых настройках окружения. Docker daemon/build требует обычного доступа к registry и PyPI; не отключайте TLS-проверку. Если DNS Docker build недоступен, сначала загрузите проверяемые pip-пакеты в `.wheelhouse` командой `.venv/bin/pip download --only-binary=:all: --dest .wheelhouse -r requirements.lock` на совместимой с образом платформе. Dockerfile использует эту папку без сети, когда она заполнена; в обычном клоне она пуста и используется PyPI. Wheel-файлы исключены из Git. Не подкладывайте непроверенные артефакты.

При read-only домашнем каталоге CLI задайте `DOCKER_CONFIG=/tmp/promo-docker-config`.

## Администрирование

Админка находится в Telegram и доступна только `ADMIN_IDS`, в личном чате. Проверка выполняется и в обработчиках, и в сервисных методах; поддельный callback не даёт прав.

- `/admin` — очередь, команды; `/queue 10` — следующая десятка.
- `/review ID` — полная карточка кандидата и кнопки публикации/отклонения.
- `/evidence ID` — JSON-файл с кандидатной или одобренной карточкой и исходным текстом.
- `/import JSON` — добавить карточку с официальной HTTPS-ссылкой. Для длинного текста пришлите JSON-документ (до 150 KB) с подписью `/import`.
- `/edit ID JSON` — исправить все поля кандидата. Документ с подписью `/edit ID` тоже поддерживается. Exchange и канонический URL существующей записи менять нельзя.
- `/approve ID`, `/reject ID` — опубликовать или отклонить. Отклонение новой ревизии сохраняет предыдущую опубликованную карточку.
- `/close ID`, `/cancel ID` — закрыть или отменить, отключить напоминания, уведомить сохранивших.
- `/stats` — число пользователей, подписок, сохранений, заданий, состояние и ошибки источников.

Проверяйте финансовые условия по оригиналу перед публикацией. Предупреждения `ambiguity` всегда требуют ручной проверки. Нажатие Publish означает, что администратор проверил источник; бот не подтверждает истинность ручных данных автоматически. Администратор не должен вставлять секреты в импортируемый текст.

Минимальный **шаблон**, не настоящая акция:

```json
{
  "exchange": "bybit",
  "source_id": "COPY_OFFICIAL_PUBLICATION_ID",
  "official_url": "https://www.bybit.com/",
  "title": "Замените названием реальной акции",
  "reward_type": "unknown",
  "raw_text": "Вставьте исходный текст официальной публикации"
}
```

Замените URL точной ссылкой на проверенную публикацию, а ID — её идентификатором. Не публикуйте шаблон как реальную акцию. Схема полей: `hunter/schema.py`. Типы награды: `withdrawable`, `trading_bonus`, `voucher`, `draw`, `pool`, `unknown`. `reward_guaranteed` — `true`, `false` или `null`; общий пул/розыгрыш не может быть гарантированным каждому. `start_at`, `end_at` принимают ISO 8601 **с явным UTC offset**, например `2026-12-01T12:00:00+00:00`. Если исходный часовой пояс неизвестен, используйте только `end_text`, без вычисления `end_at`. Отсутствующие значения — `null` или пропущенные поля. Неизвестные ключи отклоняются. Числовые условия хранятся текстом, чтобы сохранить единицы и оговорки.

Первый успешный импорт/сбор для каждой биржи создаёт baseline: уже существующие акции публикуются **без пользовательской рассылки**. Чтобы загрузить весь первоначальный набор, отправьте `/import` с JSON-массивом (1–50 карточек **одной биржи**) до последующих импортов. Весь первый массив считается baseline, а не только его первая запись. После инициализации вновь обнаруженная и одобренная акция создаёт задания для подписчиков выбранной биржи. Отдельные следующие ручные импорты считаются новыми публикациями; дату обнаружения нельзя выдавать за дату публикации.

## Источники: что проверено и что ограничено

**Обновление 2026-10-08:** Bybit возвращает HTTP 200; проверена категория `latest_activities`, получены все 11 публикаций и полные тексты. Подробности нового сборщика — ниже. Следующая таблица описывает более раннюю проверку, когда доступ был заблокирован.

Проверка 2026-10-06 из текущей среды:

| Биржа | Запрошенный официальный сайт | Результат |
|---|---|---|
| Bybit | https://www.bybit.com/ | CONNECT proxy 403 до получения страницы |
| Bitget | https://www.bitget.com/ | CONNECT proxy 403 до получения страницы |
| MEXC | https://www.mexc.com/ | CONNECT proxy 403 до получения страницы |

Это сетевой отказ среды, **не доказательство CAPTCHA на сайте**. Содержимое страниц акций/анонсов, RSS и документация API здесь не получены. Поэтому конкретные URL лент, API, CSS-селекторы и их возможности не заявляются проверенными и не задаются по догадке. На момент проверки 2026-10-06 live-интеграций не было. Теперь подтверждён сбор Bybit; fallback на тестовые данные отсутствует.

Есть отдельные `BybitAdapter`, `BitgetAdapter`, `MexcAdapter` с проверкой доменов и ручным режимом по умолчанию. Ограниченные HTML-адаптеры можно настроить после самостоятельной проверки официального источника: `{EXCHANGE}_SOURCE_URL` — точный URL официального списка публикаций, `{EXCHANGE}_LINK_SELECTOR` — проверенный CSS-селектор ссылок. Для Bitget/MEXC пустое значение даёт явную ошибку и требует ручного импорта. Для Bybit пустой SOURCE_URL теперь выбирает проверенную страницу по умолчанию, а LINK_SELECTOR не используется. У каждого адаптера `verified=False`: это допуск к автоматической публикации финансовых условий, а не статус сетевого доступа. Bybit реально собирает данные, но условия требуют модерации; AUTO_PUBLISH_VERIFIED не отключит эту проверку.

Перед включением сетевого сбора:

1. Получите официальную страницу анонсов, проверьте её доступность, правила использования/robots и ограничения частоты. Проверьте наличие RSS/API **по официальной документации**, не угадывайте адреса.
2. Укажите URL и селектор. Проверьте, что выбираются только акции, пагинация/старые записи не скрывают нужные публикации и HTML содержит текст условий. Текущий адаптер читает одну страницу списка, максимум 50 ссылок; пустой список/переполнение не инициализируют baseline. JavaScript-only страницы не поддерживаются.
3. Сохраните реальные образцы, дополните парсер и тесты; только после проверки в отдельной задаче можно изменить `verified` для соответствующего адаптера. Общий HTML-парсер сохраняет заголовок и текст, но не извлекает сложные финансовые условия из свободной прозы. Явные `data-promo-field` применяются для структурированных ручных снимков; их наличие на биржевых сайтах не предполагается.
4. Проверьте ручную модерацию первых карточек и health через `/stats`.

Интервал — `POLL_INTERVAL_SECONDS=900`; timeout 15 с, до 3 попыток при сетевых ошибках/429/5xx, backoff, минимум 2 с между запросами одного адаптера. 401/403 и redirects не обходятся. Доступны только точные домены из `DOMAINS`; поддомены по маске, IP, HTTP, credentials в URL и нестандартные порты запрещены. Нет обхода CAPTCHA, авторизации, антибот-защиты, браузерного scraping и LLM. Внешний HTML — недоверенные данные, не инструкции.

## Точность и надёжность

- Исходный текст и URL, обнаружение, последняя проверка, ревизии и решения модератора сохраняются в PostgreSQL.
- Дубли: уникальные `(exchange, source_id)` и `(exchange, canonical_url)`. Tracking/affiliate-параметры и fragment удаляются; конфликт двух существующих идентичностей требует ручного разбора.
- Кандидатная ревизия не заменяет одобренную до модерации. Изменение награды, условий, доступности или дедлайна уведомляет сохранивших после одобрения; косметические правки заголовка/описания/сырого текста не создают рассылку. Изменения смысловых полей с нормализованными пробелами сравниваются структурно.
- Карточка показывает неизвестные значения явно, тип награды отдельно, депозит как требование, а не расход. RU/UA переводят интерфейс и подписи; оригинальный текст условий не переводится автоматически. Партнёрских ссылок нет.
- Отправка — durable outbox, unique event keys, PostgreSQL `FOR UPDATE SKIP LOCKED`, 5-минутные leases, повтор после перезапуска, backoff и Telegram RetryAfter. Блокировка бота отключает отправки пользователю. Подписки и opt-out проверяются непосредственно перед отправкой. Предел — 8 попыток при сетевых ошибках, failed jobs видны в базе.
- Telegram не даёт idempotency key для `sendMessage`: при аварии после успешной отправки и до записи `sent` возможен повтор. Это **at-least-once**, не обещание exactly-once. Большая карточка делится по строкам; кнопки добавляются к последнему сообщению.
- Перед напоминанием проверяются текущие статус, подтверждённый дедлайн и свежесть проверки. Неодобренная ревизия приостанавливает напоминания. Перенос дедлайна пересчитывает время и отменяет старые задания; отмена акции отключает напоминания. Прошедший срок не отправляется. Пользователь может отменить напоминание кнопкой ✕.
- В ручном режиме нельзя проверить сайт автоматически: старше `REMINDER_FRESH_HOURS=24` напоминания удерживаются. Администратор должен перепроверить оригинал и повторно импортировать карточку, даже без изменений. Это обновляет `checked_at`. После восстановления сеть не считается рабочей без функциональной проверки.
- .env исключён из Git и Docker build context. Ошибки доставки записываются кодами без токена/тел Telegram-запросов. Установку выполняйте с проверкой TLS, без `--trusted-host` и отключения certificate verification.

## Локальная разработка и тесты

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/pip install --no-deps -e .
.venv/bin/pytest -q
```

Без TEST_DATABASE_URL тесты используют временную SQLite-базу; это проверка доменной логики, не блокировок PostgreSQL. Для отдельной **одноразовой** PostgreSQL-базы:

```bash
TEST_DATABASE_URL=postgresql+asyncpg://USER:PASSWORD@HOST:5432/DISPOSABLE_DB .venv/bin/pytest -q
```

**Тесты удаляют таблицы в TEST_DATABASE_URL. Никогда не указывайте production или рабочую демобазу.** Контракт aiogram проверяется fake Telegram transport: команды, меню, callbacks, авторизация, настройки. Тесты не обращаются к Telegram.

Исходные файлы bybit.html, bitget.html, mexc.html — **синтетические** примеры. Новые bybit-live-listing.html и bybit-live-article.html содержат реальные публичные данные Bybit, полученные 2026-10-08; посторонние скрипты исключены. Они проверяют сохранение условий, отсутствующие поля и неоднозначные даты, но не подтверждают интеграции с live-сайтами.

Для запуска вне Docker используйте собственную PostgreSQL и экспортируйте значения окружения (приложение не читает .env автоматически):

```bash
export DATABASE_URL=postgresql+asyncpg://USER:PASSWORD@HOST:5432/hunter
# BOT_TOKEN и ADMIN_IDS задайте безопасно в окружении.
.venv/bin/alembic upgrade head
.venv/bin/python -m hunter
```

Нет проверенной live-сессии Telegram: нужен локальный токен пользователя. Основные сценарии проверяются без реальной массовой отправки.

## Результат проверки в этой среде

- Финальный набор: **36 тестов прошли на отдельной PostgreSQL 16 базе**, включая конкурентные leases двух воркеров, исходные снимки, дедупликацию, initial baseline, обновления и модерацию, напоминания, перенос/отмену, opt-out, rate limits, блокировку, экранирование, финансовые ограничения и пользовательский сценарий aiogram без Telegram.
- `alembic upgrade head` выполнен; `alembic check` — `No new upgrade operations detected`.
- Docker-образ собран; демосценарий запущен и повторно запущен. После повторного запуска: 3 акции, 3 сохранения, 3 напоминания, 0 оставшихся pending jobs. Живые процессы и сообщения Telegram не использовались.
- `docker compose --profile live config --quiet`, компиляция Python и `pip check` прошли.
- Официальные сайты бирж: только попытки доступа, получен proxy 403; страницы промо/RSS/API не подтверждены. Реальный Telegram smoke test требует пользовательского токена и не выполнялся.

## Проверка реальной страницы перед автоматическим сбором

`hunter.source_check` не использует BOT_TOKEN, не запускает Telegram и не пишет в базу. Утилита сохраняет публичный HTML и перечисляет ссылки только на разрешённых официальных доменах. Ссылки в отчёте могут быть навигацией: это ещё не проверенная лента акций. Код выхода 2 означает ошибку доступа или отсутствие ссылок.

После обновления кода выполните в папке проекта на Mac:

```bash
mkdir -p source-check
docker compose --profile live build bot
docker compose --profile live run --rm --no-deps \
  -v "$PWD/source-check:/evidence" bot \
  python -m hunter.source_check --exchange bybit \
  --url 'https://announcements.bybit.com/ru-RU/?category=latest_activities' \
  --save-html /evidence/bybit.html
```

Если доступ разрешён, создаётся `source-check/bybit.html`. Утилита не перезаписывает существующие файлы: для повторной проверки задайте другое имя. По полученному HTML определите селектор и проверьте его через `--selector 'CSS_SELECTOR'`, затем проверьте текст отдельных публикаций. Если страница рендерится только через JavaScript, текущий HTTP-адаптер недостаточен: нужен документированный источник или ручной импорт, без обхода защиты. Облачная проверка 2026-10-07 по-прежнему получила CONNECT proxy 403. Домены бирж сохранены в черновике сетевых настроек; применение доступа и live-проверка остаются необходимыми.

## Рабочий автоматический сбор Bybit — 2026-10-08

Обнаружена и проверена публичная серверная структура `__NEXT_DATA__.props.pageProps`: список `articleInitEntity.list/total` на странице анонсов, `articleDetail.content_html` в публикации. Это открытые данные самой страницы, не обход CAPTCHA/авторизации и не выдуманный API. Запросы сохраняют TLS и используют существующие timeout, rate limits и backoff.

```dotenv
BYBIT_SOURCE_URL=https://announcements.bybit.com/ru-RU/?category=latest_activities
BYBIT_LINK_SELECTOR=
POLL_INTERVAL_SECONDS=900
AUTO_PUBLISH_VERIFIED=false
```

Можно оставить SOURCE_URL пустым: указанная страница используется по умолчанию. LINK_SELECTOR для Bybit больше не нужен. Настройки Bitget/MEXC пока оставьте пустыми.

После обновления кода, сохранив свой локальный `.env`, выполните:

```bash
docker compose --profile live up --build -d
```

Через минуту проверьте `/admin` и `/stats`. При первой успешной загрузке появятся карточки для проверки без пользовательской рассылки. `/review ID` показывает условия, `/evidence ID` выгружает исходный текст. Исправьте недостающие поля через `/edit ID JSON` и только потом `/approve ID`. После инициализации новые одобренные анонсы поступят подписчикам.

Сборщик сверяет категорию, номера страниц, общее число записей и идентификаторы статей; неполный список, изменение схемы, CAPTCHA или недоступная статья не инициализируют источник. Лимит — 10 страниц / 200 публикаций, без молчаливого обрезания. Проверены 11 публикаций. Сам факт категории «Промоакции» не гарантирует, что запись является отдельной акцией: в ней также встречаются обзоры и обучающие материалы, поэтому нужна модерация.

Заголовок, описание и полный текст собираются автоматически. Пошаговые условия, KYC, ограничения стран и общий пул извлекаются только из явных фраз; неоднозначные сложные требования не домысливаются. В проверенном ByPick техническая дата `end_time` равна 00:00Z, а текст указывает 08:00 UTC. Поэтому точный дедлайн остаётся неподтверждённым: период сохраняется текстом, напоминания требуют внесения подтверждённого `end_at` администратором. Технические даты CMS не выдаются за дедлайны.

Также получена официальная документация API из `bybit-exchange/docs`, файл `docs/v5/announcement.mdx`: GET `/v5/announcements/index`. Но `api.bybit.com` здесь вернул proxy CONNECT 403; этот API не используется и не заявляется live-проверенным.

Live-проверка: 11 статей и полных текстов; импорт в изолированную базу, очередь модерации, повтор без изменений и baseline без пользовательских заданий. Telegram не вызывался. Сеть проверена в облаке; доступ с вашего Mac ещё нужно подтвердить через `/stats` после запуска.
